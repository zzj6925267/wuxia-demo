## 定案 v1（先锁死，减少纠结）

以下为本阶段 **已确定** 的方案；后面要改版本，改文档版本号并写修订记录。

### A. 操作与节奏

| 编号 | 定案 |
|------|------|
| A-1 | **全自动、无玩家按键**；出手由程序判定。 |
| A-2 | **内力足够时，本回合必须走「武学主动」这条支路**（与「有蓝却整回合只普攻」相区别）；内力不足以支付武学主动消耗时，走 **普攻 / 默认行为**。（实现以 `battle.js` 为准；语义以此为准。） |

### B. 每条武学长什么样（数据约定）

| 编号 | 定案 |
|------|------|
| B-1 | 每条武学在技能表里 **至多登记 1 个「主动」**（`type === '主动'` 或项目内等价标记），其余技能为 **被动** 或被动型 effect。 |
| B-2 | 允许 **整条武学只有被动、没有主动** 的配置。 |
| B-3 | **内功回血**：**被动**承担「调息、归根、细水长流」；**初阶内功（如养气术）可不设伤害型主动**，回血与气血上限皆走被动。高阶或门派线再另设「应急一口」类主动，与被动互补。 |

### C. 治疗不搞「只有奶有冷却」的双标

| 编号 | 定案 |
|------|------|
| C-1 | **不采用**「仅治疗主动有全局冷却、输出主动无冷却」这类玩家难理解的双标规则。 |
| C-2 | 治疗与输出 **共用同一套自动战规则**；需要节制时，用 **施放条件（`if`）+ 蓝耗 + 数值** 调节，而不是单独给治疗发明第二套「能不能放」的逻辑。 |

### D. 多槽位时：谁先判、一回合放几次（核心）

| 编号 | 定案 |
|------|------|
| D-1 | 角色身上 **武功 / 内功 / 轻功** 三大类可各装备一本武学；若多本都带有「主动」，则 **无按键**，仅靠代码 **固定顺序** 判定。 |
| D-2 | **判定顺序（从高到低）**：**武功槽 → 内功槽 → 轻功槽**。 |
| D-3 | **每次完整行动至多成功施放 1 次「武学主动」**（主序一动或 D-5 速度补段一动各算一次）：从武功槽开始依次试条件；**第一个**同时满足「已解锁、够蓝、技能自带条件（若有）」的主动施放后，**该次行动不再尝试**其余槽位的武学主动。 |
| D-4 | 若三槽 **均不满足**（含：无主动、条件不满足、蓝不够）→ 本回合武学主动分支整体失败，走 **普攻 / 默认**（与 A-2 衔接）。 |
| D-5 | **速度补刀**：每名单位 **主序一次 `performAction` 结束后立刻** 与 **对位阵营存活最高速度** 比较；每领先 **一档**（`SPEED_EXTRA_ACTION_GAP`，初值 36）则 **再执行一次完整 `performAction`**（再走 D-3、可再判剑影等）；最多 **两档**（`SPEED_EXTRA_ACTION_MAX_TIERS`）。**内力**：速补段内 **`useSkill` 不扣 MP**，避免因主序耗蓝后内力不足而退回普攻（普攻无 `followSkill`，剑影等追击会消失）。**表现**：速补段气泡/日志见「速补」与 `is-speed-extra`；**同一速补 `useSkill` 内触发的追击**（剑影）也套同一套样式（`checkFollowAttack` 传入 `fxOpts`）。主序出手仍正常扣蓝。 |

> 说明：D-3 与「有内力则要走主动支路」一致——**每一次完整行动**（主序一动或 D-5 速度补段一动）内仍 **至多成功施放 1 次武学主动**；速度补段是 **额外一整次行动**，不是同一动里多槽连放。剑影等追击仍挂在对应那次 `useSkill` 内；**主序**内追击气泡/日志为默认样式，**速补**内追击与主招统一为「速补」样式（见 D-5）。

### E. 治疗主动的「条件」模板（实现时照抄 `if`，仍无按键）

| 模板 ID | 定案用途 | 条件（v1 先采用） |
|---------|-----------|-------------------|
| HEAL-01 | 单体大奶类主动 | 存在我方单位 **HP 百分比低于 40%** 时，该治疗主动 **允许进入判定**；否则本槽视为不满足，交给下一槽或最终普攻。 |
| HEAL-02 | 群体缓回类主动（若以后做） | **全队平均 HP 百分比低于 70%** 且内力不低于技能要求时允许进入判定。 |

HEAL-03（与输出互斥）在 **定案 v1** 中 **撤销**：已由 **D-3「每次行动只成一个武学主动」** 自然限制，无需再写互斥表。

**数值**（治疗量、蓝耗、递减等）：与武馆五本、后期奶装一并迭代，**本定案不锁数字**。

### F. 全被动武学

| 编号 | 定案 |
|------|------|
| F-1 | 某槽装备武学 **无主动** 时，该槽在 D-2 顺序中 **跳过**，不产生主动。 |

## 2. 青石武馆五本（本轮内容向）

**武馆线统一规格（策划定案）：** 每条武学 **固定 2 个技能** — **1 主动 + 1 被动**；**第一招 3 级解锁，第二招 6 级解锁**（不再做第三招、也不再单独为武馆线叠「凑修为」式第三被动）。武馆定位为 **纯垫修为、无炫技**：主动倍率与耗蓝偏低，数据上 **`plainFx: true`** 时战斗 **不播剑光类特效**（仅气泡 + 飘字 + 日志）。

| 武学 ID | 名称 | 主动（Lv3） | 被动（Lv6） |
|---------|------|-------------|-------------|
| 10 | 阵形剑诀 | 垫步刺 | 守拙 |
| 13 | 沉桥拳诀 | 钉小锤 | 沉肩（招架+10，根骨加成） |
| 14 | 开合刀法 | 开（bladeFx 劈斩） | 合（攻击+10，臂力加成） |
| 11 | 养气术 | 纳息（`maxHpBuff` +30 + 根骨） | 归根（`autoHeal` + 内息） |
| 12 | 挪步诀 | 挪寸（闪避+10） | 卸风（速度+10） |

与全局定案关系：武馆 **养气术** 为 **双被动**（Lv3 **纳息**：气血上限 + 根骨；Lv6 **归根**：回合回血 + 内息）；正阳等线仍可保留内功主动。内功 **归根** 与 **调息** 一样走 **`autoHeal`**，`calculateInnerSkillHeal` 对装备内功下 **所有已解锁的 `autoHeal` 被动求和**。

数据位置：`martialArtsData.js` → `MARTIAL_ARTS_LIBRARY`（id 10–14 中武馆五本）。

### 阵形剑诀（id 10）— 定稿 v1.4

| 技能 | 类型 | 解锁 | 战斗 / 面板 |
|------|------|------|-------------|
| **垫步刺** | 主动 | **3** | 有内力、武功槽装备本武学且等级≥3 时自动施放；倍率 **1.0** + 臂力 **0.006/点**；**mpCost 10**；**`plainFx`** 无剑光 |
| **守拙** | 被动 | **6** | 设计见 **§2.1**：**`defenseBuff` + `stat:'defense'`**；若用 `buff`+防御% 则战斗聚合不生效 |

**实现**：`battle.js` 武功主动仍按数据表驱动；`getAvailableSkills` 会把 **`plainFx`** 透传到 `useSkill`，有则 **跳过 `showSwordEffect`**；**无第三招「连环」追击**（已删）。

### 2.1 阵形剑诀 · 双效设计（策划定案）

**定位**：教头口令下的 **步法方位 + 剑尖守中线**，与「花剑、连招、剑光」无关；数值仍属 **武馆垫档**，表现 **`plainFx`**、无炫技。

| 槽位 | 暂定名 | 解锁 | 设计意图 | 机制定案 | 数据形态（`martialArtsData`） |
|------|--------|------|----------|----------|------------------------------|
| 主动 | **对位刺**（可沿用现名「垫步刺」） | Lv3 | 先站对方位再出一刺；能消耗内力、打出与普攻同量级的伤害即可。 | 每回合至多 **1** 次武学主动（全局定案 D）；耗蓝 **10** 左右；伤害 **`attack × (1.0 + 臂力×0.006)`** 量级，不调高倍率。 | `type:'主动'`, `effect.type:'damage'`, `plainFx:true`, `mpCost:10` |
| 被动 | **守拙** | Lv6 | 胸肋不露、剑与身成列，**有效防御略增**；不写「剑阵光环」类叙事。 | 战斗内走 **`defenseBuff`**（固定防御 + 根骨）。填表建议显式写 **`stat: 'defense'`**。 | `type:'被动'`, `effect: { type:'defenseBuff', stat:'defense', baseValue, bonusAttr:'bone', bonusPerPoint }` |

**与现表差异（落地时改数据即可）**：若将守拙从 `buff/defense%` 改为上表 **`defenseBuff`**，则被动与文档、战斗面板一致；主动仅差 **命名**（垫步刺 ↔ 对位刺）可按文案统一。

## 3. 修为：修为条与背包研读（两路都会加）

角色面板上的 **拳脚 / 剑术 / 刀术 / 轻功 / 内功修为** 总条，大致是：

**总修为（显示）≈ 角色底子（`playerCharacters` 里 `stats.*`） + 已学武学带来的修为段（各武学 `baseBonus` × 当前等级，全已学累计，与是否装备无关）。**

从 **背包研读秘籍** 学会一门武学时，**同一次成功**里会发生 **两路加成**（实现见 `inventory.js` → `learnMartialArt`）：

| 来源 | 数据在哪 | 作用 |
|------|----------|------|
| **研读额外** | 秘籍物品上的 **`cultivationGain`**（**青石武馆五本为 0**；其他秘籍仍可按表填） | 调用 `bumpMartialCultivation`，加在对应 **`skillType`** 的 **底子修为**（`stats.sword` / `stats.fist` 等）上。武馆抄本不设此路，飘字不再叠「研读 +N」。 |
| **学会武学本身** | `MARTIAL_ARTS_LIBRARY` 里该武学的 **`baseBonus`**（武馆线多为 **每级 +3** 对应一条；1 级即 +3） | 写入 `playerMartialArts_*` 后，进入 **修为条里的「武学段」**累计。 |

因此：**不是「只加飘字那一个数」**；武馆线学会时 **总涨幅主要来自 `baseBonus` 对应值**（例如剑术 1 级武学段 +3）。其他秘籍若 `cultivationGain`>0，仍会 **总涨幅 ≈ `cultivationGain` + 该武学 1 级时的 baseBonus 对应值**。策划填表时：**秘籍 `cultivationGain`** 管「抄读开窍」；**武学 `baseBonus`** 管「套路入体、随等级成长」。

**背包文案约定**：秘籍在 `items.js` 里的 **`description`** 只写来历、门派/江湖气质与武学梗概；**不写**「无研读额外修为」等策划向说明（该说明以本文档 §3 与数据字段为准）。秘籍 **`quality`** 与武学 **`rank`** 对齐时，使用 **`chu_jie` / `zhong_jie` / `gao_jie` / `jue_jie`**（背包 UI 显示为初阶、中阶、高阶、绝阶），见 `inventory.js` → `QUALITY_CONFIG`。

## 4. 跳出定案 v1 时（必须走流程）

后期新武学或新战斗机制若 **不符合** 上文定案（例如多条主动、改槽位顺序、每回合多次武学主动、治疗单独冷却等）：

1. **先改本文档**：升版本号（如 定案 v1.1）、写清「改了哪几条、为什么」，再动数据与 `battle.js`。  
2. **在 Cursor 中**：仓库已配置规则 `wuxia-demo/.cursor/rules/wuxia-martial-combat-framework.mdc`，编辑武学/战斗相关文件时助手应对照本文档；若你明确要求突破框架，助手应在对话里 **点名与哪条定案冲突**，避免无声偏离。
